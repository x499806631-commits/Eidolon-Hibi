# 06: 拍板：后台、看板和对外文档

Type: grilling
Status: resolved
Blocked by: 03, 04, 05, 08, 09

## Question

- 后台要不要设置什么（照「好感度和礼物」那次，数值多半放在代码里），还是只跟着「好感度和礼物」的开关走（定图时已定）。
- 看板要不要加一小节：任务完成率、发了多少奖励、成就解锁情况，看功能有没有人用。不落到任何一位用户。
- 隐私政策：网站多存了什么（任务进度、成就），删除时一起删。
- 使用条款：「玩法」一条要不要补上任务和成就的奖励同样没有现金价值。
- 落地页、README 三语要不要提一句；要不要发公告。
- 数据包：成就要不要随行（ADR-0025 不让好感度和礼物随行，照同一个道理多半也不随行）。每日任务的进度已定不随行。

## Comments

- 来自「拍板：成就是什么、怎么算」：成就进度不进数据包、删除用户时随之删除，「数据包」一条只剩对外文档怎么写。
- 来自「拍板：成就的奖励」：成就给抽奖次数（第 n 阶段 n 次）和集齐一位角色时的重置卡，使用条款「没有现金价值」一条要连重置卡一起说到；看板如果加一节，可以看成就发了多少次抽奖、几张重置卡。

## Answer

2026-10-20 和用户拍板：

- **后台不加设置**：门槛、奖励都是代码常量，不加开关也不加数值（只跟着「好感度和礼物」的开关，定图时已定）。配置页「好感度和礼物」卡的说明改一句，说它也管每日任务和成就。
- **看板在「好感度」分组里加一小节「每日任务和成就」，六格**：三项每日任务各做完几次；解锁了几个成就阶段、发出多少次抽奖、几张重置卡。开关开着或范围里有记录时才显示，同好感度那一节。
  - 做法：运行记录加两种 `kind`（做完一项任务、解锁一个成就阶段），哪一项、哪个成就第几阶段放进 `result`、角色放进 `character_id`（合起来的和任务为空），沿用 `record_rollups` 现有的列，不加列、不加表、不改汇总的结构。这两种不算进回合数、活跃用户（`user_rollups`）和趋势（`taken_rollups`）。上线那次补算不写运行记录。
  - 负载：每位用户一天最多 3 条任务记录，成就阶段一辈子几百个；线上每天约 12 万次服务调用，1000 位活跃用户也只多约 3000 行（约 2.5%），看板读汇总，耗时基本不变。
  - 不做：「涉及几位用户」（要像活跃用户那样按人每 15 分钟另记一份，唯一真要多存的；拿「一个回合」那项的次数对照活跃用户就够）、按成就分的表（多一张表不多一个结论）。
- **隐私政策**：在「礼物」后面新加一条「每日任务和成就」：今天每日任务做到哪了，每个成就的累计进度和解锁了哪些阶段；删除历史对话不影响、不进数据包，删除全部数据时一起删除。「运行记录」一条补上做完了哪项每日任务、解锁了哪个成就阶段。
- **使用条款**：「玩法：好感度、冷却和礼物」标题不改，末尾补一句：每日任务和成就给的抽奖次数和重置卡也一样；任务、成就的内容、门槛和奖励可能调整，已经得到的不收回。
- **对外文档**，不新开 ADR（成就不随行照 ADR-0025 的道理）：
  - `docs/configuration.md`：「好感度和礼物」一节加一段每日任务和成就（三项任务、八个成就的大意，数值以代码为准），「关掉时」补一句；后台功能表、看板一行补上面那一小节；「看不到的」一行加上每日任务和成就。
  - `docs/deploy.md` 的后台说明同样补上。
  - `docs/data-package-format.md` 「不在数据包里」那一行加上每日任务和成就的进度。
- **README 三语**：「好感度和礼物」一条后面补半句「做每日任务、解锁成就能多得抽奖次数」（英、日文对应）。礼物页截图等成就上线后重拍一张，每日任务上线时不拍。落地页不提。
- **公告**：两次上线各一条短公告，草稿写在各自的规格里，用户部署后自己在后台发。成就那条不提补算（原型票已定「上线补算不另外说明」），只说有了成就、在哪里看。
- **统计页加一节「成就」**：两个数字格——「解锁的阶段」n 个、「集齐的角色」n 位；不随时间跨度变，同「好感度」一节，放在它旁边；「好感度和礼物」关着时不出现。阶段明细不放（去她的对话页、礼物页看）。页面上不写说明。
  - 分享图不加：分享图按时间跨度算，成就是累计的，放一起会读成「近 30 天解锁了 n 个」。
  - 已改 `GLOSSARY.md`：「统计」包括成就，成就一节照成就自己记下的算、删了也不变少；「成就」一条相应改写。
- **数据包**：成就进度不随行（「拍板：成就是什么、怎么算」已定），这里只剩文档，见上。

各条归哪份规格（每日任务 / 成就）交给「拍板：两份规格的实现顺序和分支衔接」。
