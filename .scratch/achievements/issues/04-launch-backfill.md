# 04: 上线补算

**What to build:** 老用户不用从零开始。成就上线的那次启动里，从已有的回合、通话、送礼记录和好感度历史补算一次：补出来的阶段直接解锁、奖励全额到账、集齐的照给重置卡；「抽过几次奖」从 0 开始。重复部署、重启都不会再发一遍。日志里写一行补了多少。见规格「上线补算」。

**Blocked by:** 01

**Status:** done

- [x] 只跑一次：靠一行「补算过了」的标记（照 `gifts_opened` 那样的单行表，或在进度表建出来的那一刻跑），加上到账键唯一兜底
- [x] 不看「好感度和礼物」的开关：次数先进余额，开关打开以后才看得见

## Comments

### 票 03 交接

- 通话时长记在 `achievement_progress` 的 `call_time`，存的是秒，可以带小数（`calls.duration_s` 原样累加），补算直接 `SUM(duration_s)` 就和平时一致；平时只记 `keep_call` 写进了库的通话。
- 档位存 `TIERS_REACHED` 的序号（1 亲近、2 亲密），写时取 `MAX`；`achievements.keep(..., tier=...)` 只认亲近、亲密，别的档位不写。
- 「来过几天」只由回合和送礼加；通话和抽奖不算来过。

### 审查（票 04）

- 修了：`Gifts.reward` 和 `reward_everyone` 共用 `_credit`（按键到账一次）；看板断言并进「只跑一次」那条测试；`kept` 改名 `progress`。
- 没改：`launch` 返回 `(用户, (奖励, 阶段或集齐))` 的嵌套元组，和 `keep` 同形；`_launch` 用闭包带出「补算过没有」和每份奖励给的什么，同 `_happened`。补算前进度表已有行时 `MAX` 合并靠不住（上线时进度表是这次才建的，碰不到）。日志里的用户数只算真到账的人。
