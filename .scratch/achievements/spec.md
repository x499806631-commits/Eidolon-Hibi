# 成就：和她们往来得越久，解锁的阶段越多

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准（「成就」「重置卡」「统计」几条已随每日任务进了 main）。说成就、阶段、集齐、回合、通话、抽奖次数、重置卡、角色、用户、制作人，不说奖杯、徽章、称号、里程碑、羁绊、聊天。所有决定的来历在 `.scratch/daily-tasks-and-achievements/map.md` 和它的票里：定义和门槛是「拍板：成就是什么、怎么算」，奖励是「拍板：成就的奖励」，位置和样子是「原型：成就放在哪里、长什么样」（`prototype/achievements` 分支，提交 123a584，`?ac=B` 是定下的位置，导航「礼物」上的点取自 `?ac=A`），后台和文档是「拍板：后台、看板和对外文档」，和每日任务怎么衔接是「拍板：两份规格的实现顺序和分支衔接」。这份规格建立在已经合进 main 的每日任务（`.scratch/daily-tasks/spec.md`）之上。给用户看的文案要少。

## Problem Statement

- 和一位角色说了几千句话、打了几十个小时电话、送了上百件礼物，应用里什么都没留下：统计页只按时间跨度数，删了历史对话就变少；好感度到了亲密以后再往来也看不出更多。
- 每日任务给的是「今天」的收获；长期往来没有回报，也没有一个让人看得见「我们走了多远」的地方。
- 不能做成逼人打卡的东西（连续天数、错过清零），也不能变成拿钱或运气换来的东西；奖励不能直接加好感度：好感度是她的感受。
- 已经用了几个月的老用户，不该因为成就上线得晚就从零开始。

## Solution

- 八个成就，每个分几个阶段，每个阶段解锁一次、解锁了就一直在。四个按每一位角色算（和她的回合数、和她通话的累计时长、送她的礼物件数、她的好感度到过的档位），四个按所有角色合起来算（往来过几位角色、到过亲密的有几位、来过几天、抽过几次奖）。
- 第 n 阶段解锁时自动得到 n 次抽奖；某位角色按角色算的阶段全部解锁叫集齐，集齐时再得一张重置卡，每位角色一辈子只有一次。
- 按角色的成就在她的对话页里看：更多菜单最后一项「成就」打开面板。合起来的四个在礼物页每日任务下面一小节。每一行只写下一个阶段和它的奖励。
- 在她的对话页上解锁她的阶段时，页首好感度标识左边跳出奖杯和「+n」；更多菜单上留点；导航「礼物」上的点和每日任务共用。不弹提示条。
- 上线时从现有记录补算一次，补出来的阶段照常到账、照常出点，不另外说明。
- 统计页加「成就」一节，两个数：解锁的阶段、集齐的角色。

## User Stories

### 成就是什么

1. 作为用户，我想和每位角色各有一套成就，这样我和每个人的往来各自看得见。
2. 作为用户，我想有「和她的回合数」这个成就，阶段是 10、100、300、1000、3000 个回合，这样说得越多走得越远。
3. 作为用户，我想有「和她通话的累计时长」这个成就，阶段是 10 分钟、1 小时、5 小时、20 小时，从接通算起，这样打电话的时间也算数。
4. 作为用户，我想有「送她的礼物件数」这个成就，阶段是 1、10、30、100 件，这样送出的礼物留下痕迹。
5. 作为用户，我想有「她的好感度到过」这个成就，阶段是亲近、亲密，这样走近她的那一刻被记下来。
6. 作为用户，我想档位类的到过就算、之后掉下来也不收回，这样说错一句话不会让我丢掉成就。
7. 作为用户，我想有「往来过几位角色」这个合起来的成就，阶段是 3、10、28 位，和她至少一个回合就算往来过，这样认识更多角色有回报。
8. 作为用户，我想有「到过亲密的角色有几位」这个成就，阶段是 1、3、10 位，这样和几位都很亲近也看得见。
9. 作为用户，我想有「来过几天」这个成就，阶段是 7、30、100、365 天，那天有一个回合或送过一次礼就算来过，累计、不要求连续，按北京时间划天，这样断了几天也不会清零。
10. 作为用户，我想有「抽过几次奖」这个成就，阶段是 10、50、200、500 次，不看抽到了什么，这样抽奖本身也算往来的一部分。
11. 作为用户，我想没有「连续几天」这类成就，这样错过一天不会让我有挫败感、每天来也不是义务。
12. 作为用户，我想没有靠运气的成就（抽到稀有、集齐礼物），这样成就只和我做了什么有关。
13. 作为用户，我想新加的角色自动有她的一套成就，这样新角色和老角色一样。

### 怎么算

14. 作为用户，我想通话里的回合也算进「和她的回合数」，自带密钥的回合也算，这样怎么和她说话都算数。
15. 作为用户，我想只有接通的通话才算时长，这样没接通的不算。
16. 作为用户，我想删掉历史对话不会让解锁的阶段收回、也不会让进度倒退，这样删对话不会让我丢东西。
17. 作为用户，我想上线以后导入的数据包不算进成就，这样成就只认在这里发生的事。
18. 作为用户，我想「好感度和礼物」关着的那段时间里发生的事不算，这样成就和这块玩法同进退。
19. 作为用户，我想在两个标签页同时说话时同一个阶段只解锁一次、只到账一次，这样不会多拿也不会少拿。
20. 作为用户，我想被我在对话列表里隐藏的角色照样记成就、她的成就照样在她的对话页里、合起来的成就也照常算她，这样隐藏只是整理列表。
21. 作为用户，我想成就是系统记下的事、她不知道，解锁不留对话事件、她不会提起，这样她不会突然说「恭喜你解锁了成就」。

### 奖励

22. 作为用户，我想第 n 阶段解锁时自动得到 n 次抽奖，这样越往后的阶段越值。
23. 作为用户，我想不用点领取，这样不存在忘了领。
24. 作为用户，我想集齐一位角色（她的四个成就全部解锁）时再得一张重置卡，这样陪一个人走到最后有一份特别的东西。
25. 作为用户，我想每位角色的重置卡一辈子只给一次，这样规则简单、重置卡仍有分量。
26. 作为用户，我想成就给的次数不受每天发放「攒到 7 次就停」的约束、和其他次数合成一个总数，这样和每日任务一样。
27. 作为用户，我想以后门槛调低时，我已经过了新门槛的阶段在下一次相关的动作时解锁、到账，这样调低门槛不会漏掉我。
28. 作为用户，我想以后门槛调高时我已经解锁的阶段不收回，这样规则变了也不吃亏。

### 老用户的补算

29. 作为老用户，我想成就上线时从我已有的回合、通话、送礼记录补算一次，这样我不用从零开始。
30. 作为老用户，我想补算出来的阶段直接解锁、奖励全额一次到账、集齐的照给重置卡，这样我和上线后才来的人一样。
31. 作为老用户，我想「来过几天」按我已有的回合和送礼补算、档位按我的好感度历史和现在的档位补算，这样能算的都算上。
32. 作为老用户，我想「抽过几次奖」从 0 开始，因为以前的抽奖没有按人留下记录，这样不凭空编数。
33. 作为老用户，我想补算以后「礼物」上和她们对话页的更多菜单上出点，不弹窗、不加说明条，这样我自己会发现。
34. 作为部署者，我想补算只跑一次，重复部署、重启都不会再发一遍，这样不会凭空多出抽奖次数。

### 在哪里看

35. 作为用户，我想在她的对话页更多菜单最后一项点「成就」打开一个面板，这样她的成就就在和她说话的地方。
36. 作为用户，我想这个面板用她的颜色，宽屏是对话框、手机从底下拉出来，和「历史对话」一样，这样用起来熟悉。
37. 作为用户，我想面板里列她的四个成就，最后一行是「集齐」和「重置卡 ×1」，这样我知道集齐有什么。
38. 作为用户，我想每一行写着名字、阶段点（解锁的实心、没解锁的空心），下面一行只写下一个阶段（例如「420 个回合 / 1000 个回合」），这样我知道离下一个还有多远，又不会被一长串门槛淹没。
39. 作为用户，我想档位那一行写「下一个：亲密」，这样不暴露好感度的数值。
40. 作为用户，我想全部解锁的那一行写「全部解锁」、右边不再写奖励，这样一眼看出哪个已经走完。
41. 作为用户，我想每一行右边写着下一阶段的奖励「抽奖 ×n」，这样和每日任务一致。
42. 作为用户，我想集齐了「集齐」那一行变成勾和「集齐了」，这样一眼看出来。
43. 作为用户，我想合起来的四个成就在礼物页每日任务下面一小节「成就」里看，这样和抽奖次数放在一起。
44. 作为用户，我想礼物页的顺序是抽奖台、每日任务、成就、重置卡、我的礼物，这样从「能拿什么」读到「手里有什么」。
45. 作为用户，我想宽屏和手机上都能看，这样在哪都一样。
46. 作为用户，我想成就不单独成页、不在统计页列明细，这样应用不多出一个地方要找。

### 解锁那一下

47. 作为用户，我想在她的对话页上解锁她的阶段时，页首好感度标识左边跳出奖杯和「+n」（到账的抽奖次数），约 3 秒收起，这样我当场知道。
48. 作为用户，我想系统设了减少动态时奖杯不跳、只淡入淡出，这样不晃眼。
49. 作为用户，我想通话层盖着页首时不跳奖杯、只留点，这样不打断通话。
50. 作为用户，我想更多菜单键右上角出一个点、菜单项「成就」后面一个点，打开面板就消失，这样之后也找得到刚解锁的。
51. 作为用户，我想面板里新解锁的那一行名字旁有一个点，这样我知道是哪个。
52. 作为用户，我想成就到账时导航「礼物」上出点，和每日任务是同一个点、同一个意思（有新到的抽奖次数），进礼物页就消失，这样在别的角色的页面、通话里、礼物页以外解锁的也发现得了。
53. 作为用户，我想礼物页那一小节里合起来的成就新解锁时名字旁有一个点，离开礼物页算看过，这样我知道哪个新解锁了。
54. 作为用户，我想通话挂断以后才结算的通话时长阶段，过一会儿在导航和她的更多菜单上出点，这样挂断以后也知道。
55. 作为用户，我想不弹提示条，这样成就不抢她的戏。
56. 作为读屏用户，我想奖杯读作「成就，抽奖 +n」，带点的更多菜单键读作「更多，有新解锁的成就」，这样我也知道。
57. 作为用户，我想「看过」记在这台设备上，换一台设备时之前的新解锁会再出一次点，点开就没了，这样不会漏掉。

### 统计页

58. 作为用户，我想统计页有「成就」一节，两个数字：「解锁的阶段」n 个、「集齐的角色」n 位，这样一眼看到走了多远。
59. 作为用户，我想这一节不随时间跨度变，放在「好感度」一节旁边，这样它读起来是累计的。
60. 作为用户，我想这一节照成就自己记下的算，删了历史对话也不变少，这样和成就本身一致。
61. 作为用户，我想「好感度和礼物」关着时这一节不出现，这样不看到用不了的东西。
62. 作为用户，我想分享图不加成就，这样不会被读成「近 30 天解锁了 n 个」。

### 开关

63. 作为用户，我想「好感度和礼物」关着时她的更多菜单里没有「成就」、礼物页没有那一小节、统计页没有那一节，进度原样留着，这样重新打开后接着走。

### 管理者和部署者

64. 作为管理者，我想看板「每日任务和成就」小节里多出三格：解锁了几个成就阶段、发出多少次抽奖、几张重置卡，这样我知道成就发出了多少东西。
65. 作为管理者，我想上线补算不算进看板，这样看板只反映上线以后发生的。
66. 作为管理者，我想成就记录不算进回合数、活跃用户和趋势，这样原来的数字不变。
67. 作为管理者，我想门槛和奖励都是代码常量、后台不多出设置，配置页「好感度和礼物」卡的说明写上它也管成就，这样我知道关掉它会关掉什么。
68. 作为部署者，我想不用加环境变量和开关，部署前手动备份一次数据库就行，这样上线只是部署。
69. 作为部署者，我想补算在一次启动里做完、日志里写出补了多少用户和阶段，这样我知道它跑过了。

### 隐私、数据包和删除

70. 作为用户，我想隐私政策那一条改叫「每日任务和成就」，写上每个成就的累计进度和解锁了哪些阶段，这样我知道多存了什么。
71. 作为用户，我想「运行记录」写上解锁了哪个成就阶段，这样我知道管理者看得到哪些合计。
72. 作为用户，我想使用条款写明成就给的抽奖次数和重置卡也是玩法物品，内容、门槛和奖励可能调整、已经得到的不收回，这样规则说在前面。
73. 作为用户，我想成就进度不进数据包、导入也不碰，删除全部数据时一起删除，这样和好感度、礼物一致。
74. 作为用户，我想管理者看不到我的成就，只看得到所有人合起来的次数，这样和礼物一样。

### 维护者

75. 作为维护者，我想八个成就的门槛和每阶段的奖励都写成常量，这样以后调数字只改一处。
76. 作为维护者，我想成就接在每日任务建好的「发生了什么」入口和发奖励入口上，不在回合、送礼的代码里再并排加一行，这样两样东西走同一条路。

## Implementation Decisions

### 先对照 main

- 第一张票开工时，先读 main 上每日任务实际做出的往来记账（「发生了什么」入口）、幂等的发奖励入口、回合 `done` 事件和送礼返回里的「这次到账」、`GET /api/gifts` 的 `rewarded_at` 和导航「礼物」上的点、看板「每日任务」一小节，按实际的名字和形状接；这份规格里和它们对不上的地方，在那张票的 `## Comments` 里记下怎么改。

### 八个成就（常量）

| 成就 | 算法 | 阶段门槛 |
|---|---|---|
| 和她的回合数 | 每位角色 | 10 / 100 / 300 / 1000 / 3000 |
| 和她通话的累计时长 | 每位角色 | 10 分钟 / 1 小时 / 5 小时 / 20 小时 |
| 送她的礼物件数 | 每位角色 | 1 / 10 / 30 / 100 |
| 她的好感度到过 | 每位角色 | 亲近 / 亲密 |
| 往来过几位角色 | 合起来 | 3 / 10 / 28 |
| 到过亲密的有几位 | 合起来 | 1 / 3 / 10 |
| 来过几天 | 合起来 | 7 / 30 / 100 / 365 |
| 抽过几次奖 | 合起来 | 10 / 50 / 200 / 500 |

- 第 n 阶段给 n 次抽奖（常量，可调）。按角色的每位 38 次，28 位 1064 次；合起来的 32 次；一辈子最多 1096 次。
- **集齐**：某位角色按角色算的四个成就的阶段全部解锁。集齐时最后解锁的那个阶段照常给抽奖次数，另给 1 张重置卡；每位角色一辈子最多 1 张（以后加了阶段、又不算集齐了，再集齐也不给第二张）。合起来的成就不给重置卡。
- 「往来过几位」的最高一档写死 28，以后加了角色再看要不要加阶段。新加的角色自动有一套按角色的成就。
- 门槛调低：已经过了新门槛的，在下一次相关动作时解锁、到账，不另跑补算。门槛调高、阶段删掉：已解锁的不收回。阶段按序号认（第几阶段），调门槛时不改阶段的顺序。

### 记进度：接在往来记账上

- 往来记账（每日任务建的「发生了什么」入口）里加成就这一份，并补三处调用：
  - **回合记下了**（已有）：她的回合数加一；那一天是新的一天就让「来过几天」加一；看她现在的档位（见下）。
  - **礼物送出了**（已有）：送她的件数加一；「来过几天」同上；看她现在的档位。
  - **通话结束了**（新加）：只有接通过的通话；她的通话累计秒数加上这次的时长。放在通话结算、通话记录写进库以后（现在是 `CallOutcome` 结算时的 `keep`）；那里要能拿到用户和角色。
  - **抽过奖了**（新加）：抽了几次就加几次。放在 `Gifts.draw` 提交以后、放开礼物模块的锁以后再调（锁不可重入）。
  - **档位**：回合和送礼之后看她现在的档位（判断和送礼都会给出变化后的档位），到了亲近就算到过亲近，到了亲密两个阶段都算到过；不另外挂在好感度模块的内部。自然恢复只会回到正常值、重置卡也只拉回正常值，都碰不到亲近，所以不用在那两处看。
- 合起来的「往来过几位」「到过亲密的有几位」由按角色的进度推出来（和她的回合数至少 1 的有几位、档位到过亲密的有几位），不另存一份。「来过几天」存累计天数和最后一次来的那一天（北京时间，按注入的时钟）；「抽过几次奖」存累计次数。
- 开关关着时往来记账什么也不记（每日任务已经这样）；出错时只记日志、不让动作失败（同每日任务）。数据包导入、删历史对话都不经过它。
- 每次记进度后，按当前的门槛算出已经到了哪些阶段，没解锁过的就解锁、到账；接着看这位角色是否集齐。这些和进度的写入、到账记录、`gift_balances` 的修改在同一个事务里（同每日任务）。

### 存什么

- **成就进度**：按（用户、成就、角色）一行累计数；合起来的那几个角色为空。档位类存到过的最高档位。
- **解锁的阶段**：按（用户、成就、角色、第几阶段）一行，带解锁时刻；唯一。
- 「来过几天」的最后一天可以放进进度那一行。
- 奖励到账走每日任务建的发奖励入口，补上「加 M 张重置卡」：阶段的键形如「成就、角色、第几阶段」，集齐的键形如「集齐、角色」。键唯一，所以同一阶段只到账一次、每位角色的重置卡只有一次。
- 新表都登记进 `database.py` 的 `USER_DATA`；不进数据包。

### 上线补算

- 在 `Gifts`/往来记账建表的那次启动里跑一次，靠一行「补算过了」的标记保证只跑一次（照 `gifts_opened` 那样的单行表，或者在进度表建出来的那一刻跑）；再加上到账的键唯一，重复部署、重启都不会再发。跑的时候不看「好感度和礼物」的开关：补的是历史，次数先进余额，开关打开以后才看得见。
- 从现有记录算，能算的都算，连上线前导入的数据包记录一起算（只此一次）：
  - 每位角色的回合数：`messages` 里用户说的那一行，连 `conversations` 取角色。
  - 每位角色的通话累计时长：接通过的 `calls` 的时长，连对话取角色。
  - 每位角色的送礼件数：`conversation_events` 里的送礼记录。
  - 档位到过：她回复上记下的好感度变化（`messages.affinity` 的档位）、送礼记录上的变化，加上现在的档位。
  - 来过几天：回合和送礼记录的时刻按北京时间划天，数不同的天；最后一天取最近的那一天。
  - 往来过几位、到过亲密的有几位：同平时，由按角色的推出来。
  - 抽过几次奖：没有按人的记录，从 0 开始。
- 补出来的阶段直接解锁、奖励全额到账（不封顶、不折算），集齐的照给重置卡。补算不写运行记录、不进看板。解锁时刻记成补算的时刻，所以前端照常出点。
- 用聚合查询在一个事务里做完；日志写一行补了多少位用户、多少个阶段、发出多少次抽奖和几张重置卡。

### 到账了什么：随回合、送礼一起返回

- 往来记账返回的「这次到账」加上：解锁了哪些阶段（成就、角色、第几阶段、给了几次抽奖）、集齐了哪位角色（给了几张重置卡）。打字回合、通话里回合的 `done` 事件和送礼的返回已经带着这个字段。
- 通话时长和抽奖解锁的阶段：抽奖接口的返回也带上「这次到账」；通话结算时没有可以带回去的响应，靠轮询（见下）。

### 接口

- 她的成就：新加 `GET /api/characters/{id}/achievements`，返回她的四个成就（每个的累计进度、各阶段的门槛和奖励、已解锁阶段的解锁时刻），和集齐那一行（是否集齐、集齐时刻、给几张重置卡）。开关关着时返回 null。
- 合起来的成就：`GET /api/gifts` 加 `achievements`，同样形状的四个。开关关着时为 null。
- 抽奖的返回带「这次到账」（抽到第 10、50…次时）。
- 档位只给档位名，不给数值。

### 「看过」和点

- 都只记在这台设备上，和每日任务的导航点用同一个 `lib/` 模块（或同一套做法）：localStorage 里按用户存，按范围（某位角色、合起来）记看过的最近解锁时刻；存储不可用时退回这一页的内存；还没存过时任何解锁都算没看过（所以上线补算照常出点）。
- **导航「礼物」上的点**：成就到账同样更新 `rewarded_at`，不用另做。
- **她的更多菜单键和菜单项「成就」上的点**：她的最近解锁时刻晚于看过的就亮。对话页打开时读她的成就；回合返回里带着她的阶段时当场亮；外壳轮询读到 `rewarded_at` 变新时，正开着的对话页重读她的成就（通话挂断后结算的时长阶段靠这条）。
- **面板里那一行的点**：打开面板时，解锁时刻晚于打开前看过的时刻的那几行带点；打开面板就把看过记成她的最近解锁时刻，点保留到面板关上。
- **礼物页那一小节的点**：解锁时刻晚于看过的那几行带点；离开礼物页时记成看过。
- 哪一行带点、菜单键亮不亮收进 `lib/` 纯函数。

### 她的对话页

- 更多菜单最后加一项「成就」（新图标放进 `theme/icons`），开关关着时没有。
- 面板照 `PastConversations` 的做法：宽屏 `Dialog`、窄屏 `Drawer`，重新注入她的颜色。四行加最后一行「集齐」。
- 每一行：名字；阶段点（解锁的实心、没解锁的空心）；下面一行只写下一个阶段：回合「420 个回合 / 1000 个回合」、通话「3 小时 12 分 / 5 小时」、礼物「12 件 / 30 件」、档位「下一个：亲密」，全部解锁写「全部解锁」；右边下一阶段的奖励「抽奖 ×n」，全部解锁就不写。「集齐」一行：没集齐是空圈、「集齐」、「重置卡 ×1」；集齐了是勾、「集齐了」。各行的名字照原型 `?ac=B`。
- 每一行写什么（下一个阶段、进度文字、是否全部解锁、奖励）收进 `lib/` 纯函数，面板和礼物页那一小节共用。
- **奖杯**：回合返回里带着这位角色的阶段、而且通话层没盖着页首时，页首好感度标识左边跳出奖杯和「+n」（n 是这次她的阶段到账的抽奖次数），约 3 秒收起；照顾减少动态。照 `AffinityBadge` 变化提示的做法（带 key 的一次性提示，由 `LiveConversation` 的快照给出，过一段时间清掉）。读屏用礼貌的 live region 读「成就，抽奖 +n」。通话层盖着时不跳，只留点。合起来的成就在她的页上解锁时不跳奖杯，只出导航上的点。
- 带点的更多菜单键读作「更多，有新解锁的成就」。

### 礼物页那一小节

- 每日任务下面、重置卡上面一小节「成就」，四行：往来过的角色、到过亲密的角色、来过的天数、抽过的奖；每行和面板里的写法一样（「5 位 / 10 位」「12 天 / 30 天」「37 次 / 50 次」）。
- 送礼、抽奖返回里带着解锁时当场更新，然后照现在的做法重读 `GET /api/gifts`。
- 用现有的 shadcn 部件和礼物页已有的分节样式，照 `frontend/AGENTS.md` 的「shadcn 纪律」，视觉以 `DESIGN.md` 为准；`DESIGN.md` 补上成就面板、奖杯和更多菜单上的点。

## Testing Decisions

- 只测对外的行为：接口返回的阶段和进度、抽奖次数和重置卡、回合和送礼返回里的「这次到账」、看板和统计页的数、库里留没留下东西，不测进度表怎么存、补算的查询怎么写。
- **后端只走现有的 HTTP 接缝**：`make_client` 加 `FakeClock`、`FakeServiceClients`、`FakeRandom`（判断模型照 `test_gift_draws.py` 打开好感度和礼物；档位靠假判断的升降推上去）。回合用 `send_turn`，送礼、抽奖用各自的接口，通话照 `test_call_stats.py` 的通话测试驱动，结果从 `GET /api/characters/{id}/achievements`、`GET /api/gifts`、`GET /api/stats`、后台看板接口看。
- **上线补算**：先用 sqlite 直接往库里塞回合、通话、送礼记录和好感度历史（照现有测试直接改库的先例），再建 client，从接口看补出来的阶段、抽奖次数和重置卡；再建一次 client（模拟重启）确认不再发。门槛很高的阶段（3000 个回合、20 小时）测试里用改常量（monkeypatch）的办法降下来，不真造那么多记录。
- **后端要测的**：
  - 八个成就各自解锁的时机，第 n 阶段给 n 次；一次跨过几个阶段时几个都解锁、都到账。
  - 档位：到过亲近、直接到亲密时两个都解锁；掉下来不收回。
  - 集齐给 1 张重置卡；调了常量（加一个阶段）以后再集齐不给第二张。
  - 门槛调低后下一次动作时解锁；调高不收回。
  - 通话：只有接通的算、累计；通话里的回合算进回合数。
  - 来过几天：同一天多次只算一天，跨北京时间 0 点算两天，不要求连续。
  - 往来过几位、到过亲密的有几位由按角色的推出来。
  - 抽奖：抽一次、全部抽完都算次数；抽奖返回里带着解锁。
  - 开关关着不记、接口返回 null；删历史对话不倒退；导入数据包不前进；两个并发回合只到账一次。
  - 补算：各项的来源、数据包导入的旧记录也算、抽奖从 0 开始、只跑一次、不写运行记录。
  - 看板三格、标题那一小节；统计页「成就」一节两个数、开关关着为 null、删了历史对话不变少。
  - 删除用户后新表不剩这位用户的行（`test_database.py` 检查登记）。
  - 先例：每日任务分支留下的测试（往来记账、到账、导航点），加上 `test_gift_draws.py`、`test_gift_giving.py`、`test_affinity_turns.py`、`test_call_stats.py`、`test_affinity_dashboard.py`、`test_activity_records.py`、`test_stats.py`、`test_reset_card_grants.py`（重置卡）、`test_delete_past_conversations.py`、`test_data_package_conversations.py`、`test_delete_account.py`、`test_database.py`。
- **前端只测 `lib/` 里的纯函数**：
  - 每一行的写法：下一个阶段、各类进度文字（回合、时长、件数、档位、位、天、次）、全部解锁、奖励、集齐一行。
  - 点：更多菜单键亮不亮、面板里哪几行带点、礼物页那一小节哪几行带点、看过以后不亮、新解锁又亮、存储不可用时退回内存、没存过时补算出来的都亮。
  - 奖杯：回合 `done` 带着她的阶段时给出一次带 key 的提示、过一段时间清掉；别的角色的、合起来的不给；通话层开着时不给（照 `liveConversation.test.ts` 的 `FakeCall` 和假 ports）。
  - 统计页「成就」一节什么时候出现（`stats.test.ts`），看板那一小节（`dashboard.test.ts`）。
- **验收**：面板在宽屏和手机上的样子、奖杯跳一下、更多菜单和面板上的点、礼物页那一小节、统计页那一节、上线补算后的点、通话挂断后时长阶段的点，按 `docs/agents/local-acceptance.md` 在本地构建版上用 Playwright 自己看；能用接口或改库造出的状态就自己造，只把要人看的留给用户。
